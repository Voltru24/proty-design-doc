# GDD — Система наёмников

Проект: Proty (Godot 4.7.2 mono, GDScript)
Статус: Дизайн (не реализовано)
Дата: 2026-09-14
Связано: guild-simulator.md (Фаза 2 — планирование заданий)

---

## 1. Цель

Дать гильдмастеру **кадровый ресурс**: два класса наёмников с разным
риск-профилем, чтобы каждый визит в Фазу 2 был взвешенным решением
(кого послать, кому передохнуть, где грань между риском и наградой).

Столбы:
1. **Случайные — расходник, но каркас.** Дешёвые, заменяемые, но на боевых
   заданиях **могут погибнуть**.
2. **Сюжетные — инвестиция.** Уникальные персонажи, которые **не умирают**,
   но получают дебаффы; их смерть невозможна по лору.
3. **Риск читается заранее.** Игрок видит вероятность смерти/травм **до**
   отправки, а не узнаёт после.

---

## 2. Классы наёмников

| | Рандомные (случайные) | Сюжетные |
|---|---|---|
| Источник | **приходят как самостоятельные визитёры** в гильд-холл (визитёр = клиент **или** наёмник) | события, квесты, новости |
| Создание | процедурная генерация | рукописные персонажи |
| Стоимость найма | низкая/средняя | высокая (или через цепочку) |
| Сила | базовая, средняя | выше среднего + уникальные черты |
| Смерть на боевом | **ДА** | **НЕТ (никогда)** |
| Дебаффы | да (как и у всех) | да (механика не щадит) |
| Замена | легко (новый из пула) | нет (инвестиция, потеря невозможна — только «выгорание») |
| Сюжетная роль | нет | личные арки, диалоги, секреты |

Ключевое правило: **смерть возможна только на боевом задании и только у
рандомных**. У сюжетных исхода «смерть» не существует: при провале они
получают дебафф и/или сюжетное последствие.

## 3. Характеристики

Базовая карточка наёмника:

- **Имя/портрет** (рандом: из словаря-имён; сюжетный: рукописный).
- **Роль** (боец, целитель, следопыт, маг) — пригодность к боевым/мирным.
- **Уровень** (1…10 MVP) — потолок статов.
- **Основные характеристики — 6 шт.: 3 боевых + 3 мирных.**

  | Группа | Характеристика | Влияет на |
  |---|---|---|
  | Боевые | **Сила** | урон, ношение брони, физическая работа |
  | Боевые | **Ловкость** | уклонение, точность, ловушки, скрытность |
  | Боевые | **Выносливость** | здоровье, устойчивость к травмам/дебаффам |
  | Мирные | **Интеллект** | магия, исследования, знание |
  | Мирные | **Мудрость** | наблюдательность, лечение, выход из трудностей |
  | Мирные | **Обаяние** | убеждение/переговоры, работа с клиентами (Фаза 1), командный дух |

  Диапазон статов 1–10 ✓ (у рандомных суммарный «бюджет» фиксирован: сильные в
  бою слабеют в мирном и наоборот — читаемый трейд-офф).

- **Дополнительные навыки — 1–3 шт.** (кулинария, письменность/грамота,
  травничество, ремесло, зельеварение, красноречие, картография, слежка,
  верховая езда, скоризм и т.п.). **Генерируются из предыстории** наёмника
  (§3.1): каждая предыстория имеет собственный список допустимых навыков,
  из которого выбираются 1–3. Навык влияет на пригодность к **мирным**
  заданиям (документы — письменность, травы — травничество) и открывает
  особые успехи/события в миссиях.

- **Черта характера — 1 (у сюжетных 1–2, уникальные).** Черта **влияет на
  поведение**, а не только на цифры (§3.2).

- **Занятость**: текущее задание или свободен.
- **Состояние здоровья**: здоров / травмирован(ы)/ устал / проклят и т.п.

Итоговая «сила отряда» (используется в формуле исхода миссии §7 guild-simulator):
`SquadPower = Σ (боевые статы по роли + уровень·10 + мирные статы/2 + бонусы навыков)`
с учётом дебаффов и черт характера.

### 3.1. Предыстории (источник дополнительных навыков)

У каждого наёмника (и клиента — для глубины) есть **предыстория**. Она
задаёт: вводную фразу, список кандидатов на доп-навыки.

| Предыстория | Всегда/часто даёт | Может дать |
|---|---|---|
| Крестьянин | ремесло, кулинария | верховая езда, ловкость рук |
| Писарь/писарка | письменность, картография | красноречие, знание законов |
| Знахарь | травничество, зельеварение | леч-навык |
| Бывший стражник | слежка, строй | ремесло, знание города |
| Торговец | красноречие, письменность | картография, оценка |
| Странник | картография, слежка | кулинария, верховая езда |

Генерация рандомного: предыстория → 1–3 навыка из её списка → черта → статы
(по бюджету группы). Сюжетные: предыстория рукописная, навыки фиксированы.

### 3.2. Черты характера (влияют на поведение)

| Черта | Эффект на поведение |
|---|---|
| Смельчак | сам напрашивается на боевые; +fit в бою |
| Трусливый | отказывается от боевых при риске смерти > 15%; шанс «слинять» из миссии |
| Жадный | требует бóльшую долю награды; при выторгованной высокой цене лояльнее |
| Верный | не подведёт; +командный дух, не уходит после дебаффов |
| Гордец/Упрямый | может отказаться от приказа (смена задания в холле) |
| Общительный | +синергия в отряде, лучше в мирных «клиентских» миссиях |
| Подозрительный | −синергия с незнакомцами, но +надёжность против ловушек/обмана |
| Ленивый | быстро накапливает Усталость, копится чаще Деморализация |

Черта видна на карточке (⚠), но **не все её эффекты раскрыты** — некоторые
проявляются первый раз в миссии (сообщение-событие: «Трус не выступил,
похоже, он в кустах»). Сюжетные черты уникальны и связаны с их арками.

## 4. Рекрутинг

**Рандомный пул (визитёры гильд-холла):**
- В гильд-холл приходят **визитёры из общего пула — как клиенты, так и
  наёмники** (§1/§3 guild-simulator.md + данный документ).
- Клиент-визитёр несёт **контракт** (Фаза 1); наёмник-визитёр — **предложение
  о найме** (Фаза 2-кадры). Один заход = один персонаж: либо клиент, либо наёмник.
- Наёмник виден как карточка-кандидат: роль, статы, черты, цена найма +
  короткая фраза-самопрезентация.
- **Найм возможен прямо в гильд-холле**: кнопка «Нанять» у кандидата.
  Не нанял сейчас — визитёр уходит; новые наёмники придут с новыми заходами.
- Пул визитёров общий (клиенты и наёмники), вероятность исхода визита
  настраивается балансом — он связывает Фазу 1 (контракты) и Фазу 2 (кадры)
  в один конвейер.
- Найм стоит золота (базовая формула: `30 + уровень²·5` монет).
- Удача и «скрытые пороки» могут вскрываться позже.

**Сюжетные**:
- Появляются через события (контракты особого типа, новости, цепочки).
- Найм — часто не деньги, а выполнение цепочки из 2–3 условий (репутация,
  личный контракт, диалог).
- 1 сюжетный = «буфер безопасности» гильдии: никогда не потеряешь его.

## 5. Смерть и дебаффы

### 5.1. Что даёт боевое задание
Риск исхода разбит на **два этапа** (до отправки игрок видит оба числа):

1. **Шанс общего провала** (уже в guild-simulator §7) — контракт не выполнен.
2. **Шанс потерь** внутри отряда при боевом задании (даже при успехе возможен
   случайный вред):

```
death_chance_i   = clamp( 0.02слот * (1 - fit_i²) * U * RiskLevel , 0.005, 0.30 )
injury_chance_i  = clamp( 0.15слот * (1 - fit_i²) * U               , 0.02, 0.60 )
```

- `fit_i` — пригодность наёмника к заданию (0…1; роль + основные статы +
  доп-навыки + черты под тип миссии; мирные дают `death_chance = 0`).
- `U` — множитель срочности (low 0.7, normal 1.0, high 1.3, critical 1.6).
- `RiskLevel` — скрытая сложность контракта (0.5 лёгкий … 1.5 хардкор).

**Порядок:** сначала roll injury у каждого → потом roll death только у тех,
кого не спасла Выносливость/черты. Мертвецу дебафф не нужен; травма может
«сгореть» в смерть.

### 5.2. Рандомные
- При `death`: наёмник удаляется из состава. Гильд-холл показывает причину
  («погиб при выполнении контракта…»), репутация гильдии −5 (родня/город),
  возможно «письмо вдове» как разовый контракт-событие.
- Каждая боевая миссия обязана иметь **минимум жизнеспособности**: выведи
  текущий расчёт `fit` для худшего наёмника в карточке миссии.

### 5.3. Сюжетные
- **Никогда не умирают.** При попадании смерти → конвертируются в **тяжёлый
  дебафф** + сюжетное последствие (недоступен на 2–3 «дня», разговор в холле,
  новый персональный контракт «лечение/отмщение»).
- Механика одна и та же: `injury` всегда работает, `death` у сюжетных
  превращается в «выбывание» (долгий дебафф, не смерть).

### 5.4. Примеры дебаффов

| Дебафф | Эффект | Спадает |
|---|---|---|
| Травма (лёгкая) | −20% статов | лечение 2 дня |
| Травма (тяжёлая) | −40% статов, нельзя на боевое | лечение 5 дней / целитель |
| Усталость | −15% статов | отдых 1 день |
| Деморализация | −10% и шанс отказаться от боевого | успешная миссия / пир |
| Проклятие | −30% надолго, подрывает навыки/черты | квест «снять проклятие» |
| Выбывание (сюжетн.) | недоступен 2–3 дня | время / личный контракт |

Баланс: дебаффы — главный «износ» сюжетных; даже идеальная команда
периодически нуждается в ротации.

## 6. Модель решения игрока

На каждое задание (из Фазы 1) гильдмастер решает:
1. **Кого слать** — состав по типу (боевой требует боец+целитель; мирный —
   следопыт/маг) и уровню сложности.
2. **Рисковать ли сюжетным** — он не умрёт, но дебафф выбьет его из ротации.
3. **Выжать ли рандомных** — дёшево, но смерть рандомного = минус репутации
   и кадровый провал.

Журнал/память: после каждого задания — однострочный отчёт («Октав получил
тяжёлую травму»), чтобы игрок видел износ.

## 8. Скриптовая схема (для реализации позже)

```
hire_roster.gd
 ├─ recruit_pool: генерация рандомных
 │    (имена → предыстория → навыки 1–3 → черта → статы по бюджету)
 ├─ story_pool: рукописные (const Dictionary / .tres)
 ├─ calculate_fit(hero, quest) → fit 0..1  (статы + навыки + черты)
 ├─ simulate_personality(hero, mission) → отказы/события от черт
 ├─ resolve_mission(quest, squad) → success + injuries + deaths
 │    (death roll: только рандомные + только боевой тип)
 └─ apply_debuff(hero, debuff) / remove_debuff(...)
```

## 9. Scope / Non-goals (MVP)

**В MVP:**
- Визитёры — общий пул: **клиенты и наёмники**; в начале приходит 6 клиентов
  (guild-simulator §3), стартовый наёмник может прийти с первых волн визитов.
- Роли боец/целитель/следопыт/маг, **6 основных статов (3 боевых + 3 мирных)**,
  **доп-навыки из предысторий (1–3)**, **черты характера**, 6 дебаффов, формулы §5.
- Смерть только: рандомный + боевой + `death_chance`. Сюжетный → выбывание.
- Ростер-экран, занятость, отчёты после миссии.

**Не в MVP (future):**
- Прокачка статов вручную, снаряжение/инвентарь, восстановление целителями
  в бою, дуэли/обучение, смерть внутри сюжетных арок (дебафф + событие).

## 10. Acceptance criteria

1. Рандомный пул генерирует ≥3 кандидатов: всё из карточки — роль, 6 статов,
   предыстория, 1–3 доп-навыка (из списка предыстории), черта, цена.
2. Сюжетный наёмник не удаляется никогда (в т.ч. при срабатывании death-roll —
  вместо смерти «выбывание»).
3. `death_chance = 0` для мирных заданий и для сюжетных (у них — выбывание).
4. Карточка миссии показывает fit, шанс травмы и шанс смерти **до** отправки.
5. Черта влияет на поведение: хотя бы одна черта даёт событие/отказ в тестовой
   миссии (напр. Трусливый при высоком риске).
6. Дебафф спадает по таймеру; тяжело-травмированный не назначается на боевое.
7. После миссии в журнал пишется отчёт о потерях/дебаффах.
8. Полный цикл: найм → назначение → исход → отчёт, без ошибок (смоук-тест).

## 11. Открытые вопросы

1. **Вероятность «визит = наёмник»** у общей линейки: с какими коэффициентами
   клиенты и наёмники чередуются в пуле визитёров?
2. **Сюжетные:** когда выдаётся первый? (в начале — поздно?) И можно ли их
   «потерять» иначе, кроме смерти (например, предательство — как дебафф/событие)?
3. **Нужны ли мирные контракты, чтобы развивать сюжетных** (лечение/арки), или
   дебаффы только игровой износ?
4. «Смерть» рандомного — только при провале миссии или и при успехе (см. §5.1)?
5. **Доп-навыки**: влияют ли на боевые задания (напр., ремесло — «починить инвентарь,
   +шанс»), или только на мирные и особых события?
6. **Черты характера**: раскрывать игроку полные эффекты сразу или втыкать
   «скрытые» события (сюрприз в миссии)? (см. §3.2 — предложен вариант скрытых)
